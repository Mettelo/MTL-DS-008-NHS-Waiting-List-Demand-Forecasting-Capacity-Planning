# Team Submission Guide

## Step 1 — Confirm the Team Repository

Use one repository for the team's delivery.

Recommended naming:

```text
MTL-DS-008-<team-name>
```

## Step 2 — Add Team Members

Each team member should use their own GitHub account.

Do not share one GitHub login between contributors.

## Step 3 — Work Through GitHub

During delivery:

- create issues for meaningful work;
- use branches for substantial changes;
- make descriptive commits;
- use pull requests for material merges;
- review important changes;
- keep contribution evidence current.

## Step 4 — Give Mettelo Organisation Access — Mandatory

Your delivery repository must be accessible to the **Mettelo GitHub organisation** before submission.

### Preferred setup

Create the repository inside the **Mettelo GitHub organisation** where possible.

### If the repository exists outside Mettelo

Do not assume you can invite the organisation directly.

Before submission, follow the access route provided by Mettelo. This may mean:

1. transferring the repository into the Mettelo GitHub organisation; or
2. granting access to the Mettelo reviewer account/team specified for the cohort.

### Mettelo must be able to inspect

- project files;
- commit history;
- branches;
- issues;
- pull requests;
- contribution records;
- tests;
- documentation;
- final deliverables.

**Your submission is not complete until Mettelo organisation access has been verified.**

Keep this access active until review and verification are complete.

## Step 5 — Complete FINAL_SUBMISSION.md

Update:

```text
submission/FINAL_SUBMISSION.md
```

Make sure it includes:

- team name;
- Team Lead;
- repository URL;
- final branch;
- final tag/release;
- deliverable links;
- contribution evidence;
- known limitations;
- reproduction instructions.

## Step 6 — Final QA

Confirm:

- [ ] repository naming is correct;
- [ ] Mettelo organisation access has been granted and verified;
- [ ] all team members use their own accounts;
- [ ] repository history shows collaborative work;
- [ ] documentation is complete;
- [ ] setup/reproduction instructions work;
- [ ] tests or validation steps are documented;
- [ ] final deliverables are accessible;
- [ ] no secrets or credentials are committed;
- [ ] contribution evidence is complete.

## Step 7 — Submit the Repository URL

The official submission is the team's GitHub repository URL.

Do not submit project files by email.

## Step 8 — Freeze the Submitted Version

Create a tag or release:

```text
v1.0-mettelo-submission
```

Mettelo will review the tagged version unless otherwise agreed.
